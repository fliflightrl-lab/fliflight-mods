# C — CurseForge Rewards + funnel CF-first

## 1. CurseForge Rewards — vérifier & activer (à faire côté compte)
Les Rewards = part de revenus publicitaire basée sur les **téléchargements CurseForge**,
payée via PayPal au-delà d'un seuil. C'est la seule source « automatique » de revenus.

**Checklist (connexion à ton compte CF requise — je ne peux pas le faire à ta place) :**
1. Connecte-toi sur https://www.curseforge.com puis **Authors → Rewards** (ou
   `authors.curseforge.com`).
2. Vérifie que le compte est **enrolled** (inscrit au programme). Sinon, inscris-toi.
3. Sur **chaque** projet → section **Rewards / Monetization** → assure-toi que la
   monétisation est **ON** (par défaut elle l'est, mais à confirmer).
4. Vérifie la méthode de paiement (PayPal) et le seuil de versement.
5. Note : **seuls les téléchargements CurseForge comptent** — pas Modrinth, pas GitHub.

➡️ Action immédiate : les ~83 500 téléchargements déjà faits ne « re-rentabilisent » pas
rétroactivement (les Rewards sont mensuels), donc l'enjeu est de **maximiser les
téléchargements CF futurs**.

## 2. Funnel CF-first (règle d'or)
**CurseForge = là où tu es payé. Tous les autres canaux = des entonnoirs vers CF.**

| Canal | Rôle | Lien à mettre |
|---|---|---|
| CurseForge | 💰 conversion (Rewards) | — |
| Modrinth | portée (launchers alternatifs) | description → lien CF (pas l'inverse) |
| GitHub Releases | backup + découvrabilité | lien CF en tête de release |
| Planet Minecraft | trafic énorme (resource packs) | **bouton download → CF**, pas le fichier direct |
| YouTube/TikTok/Reddit | acquisition | lien CF en description + épinglé |
| Discord | communauté + annonces | liens CF des nouveautés |

⚠️ Piège courant : publier le fichier **directement** sur PMC/GitHub/Modrinth « pour
faciliter » = tu perds le téléchargement CF (et donc le Rewards). Le fichier reste
disponible partout, mais **l'appel à l'action** doit toujours ramener vers CF.
